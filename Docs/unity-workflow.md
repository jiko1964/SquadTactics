# Unity開発ワークフロー

「3人部隊ターン制対戦ボードゲーム」（ルールブック v1.1）を Unity で制作するための進め方。
原則：**オンライン対戦は最後。まず1人で遊べるプロトタイプを完成させる。**

---

## 1. 必要なソフト

### 必須

| ソフト | 用途 | 備考 |
| --- | --- | --- |
| Unity Hub | Unity本体の管理 | ここから Unity 6（LTS）をインストール |
| Unity 6 LTS | ゲーム本体 | 新規プロジェクトは「2D」テンプレートで作成 |
| Visual Studio 2022 | C#のコーディング | インストール時に「Unityによるゲーム開発（Game development with Unity）」ワークロードを選択。代替：VS Code / Rider |
| Git | バージョン管理 | Unity用の `.gitignore` を必ず入れる（Library フォルダ等を除外） |
| GitHub | リポジトリ置き場 | 接続済みアカウント `jiko1964`、ゲーム用リポジトリ `jiko1964/SquadTactics` を使用中（文書は Docs フォルダで管理） |
| Git LFS | 画像・音声など大きな素材の管理 | 素材が増えてきたら導入 |

### あると便利

| ソフト | 用途 | 備考 |
| --- | --- | --- |
| Aseprite | ドット絵（キャラ・タイル） | 有料だが安い。無料なら Krita / GIMP |
| Krita / GIMP | 画像編集全般 | 無料 |
| Audacity | 効果音・BGMの編集 | 無料 |
| フリー素材サイト | 仮素材・効果音 | itch.io、効果音ラボなど。プロトタイプ段階は素材にこだわらない |

数値をコードに直書きしないことで、バランス調整がコード変更なしでできるようになる。

## 3. 実装上の注意（このゲーム特有）

1. **戦闘ロジックは表示と分離する**：命中計算・ターン解決は MonoBehaviour に依存しない純粋な C# クラスで書く。テストしやすく、オンライン同期のときにもそのまま使える。
2. **乱数はシード管理する**：命中判定などの乱数は試合開始時に決めたシードから生成する。リプレイ検証とオンライン同期で必須になる。
3. **最初からオンラインを作らない**：プロトタイプ（フェーズ1）が面白くなければ、後工程はすべて無駄になる。
4. **数値はデータに逃がす**：武器・キャラ・マップはすべてデータ（ScriptableObject / JSON）で持ち、コードは「ルール」だけを担当する。
5. **こまめにコミット**：フェーズのチェック項目1つ終わるごとに Git にコミットする。壊れても戻れる状態を保つ。
